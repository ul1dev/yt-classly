# Студия

Русскоязычное приложение для двух филиалов групповой студии. Клиенты регистрируются по email и паролю, выбирают филиал в расписании, видят собственные записи и остатки абонементов. Владелец управляет обоими филиалами, клиентами и администраторами филиалов. Администратор филиала управляет занятиями и записями своего филиала и выдаёт абонементы только для него.

## Локальный запуск

1. Установите зависимости: `npm install`.
2. Создайте bcrypt-хеш пароля тестового администратора: `node -e "console.log(require('bcryptjs').hashSync('ВАШ-ДЛИННЫЙ-ПАРОЛЬ', 12))"`.
3. Скопируйте `.env.example` в `.env` и заполните `ADMIN_EMAIL` и `OWNER_PASSWORD_HASH`. В файле `.env` заключите bcrypt-хеш в одинарные кавычки, чтобы символы `$` сохранялись буквально.
4. Запустите `npm run dev` и откройте `http://localhost:5173`.

При первом запуске с `ADMIN_EMAIL` создаётся аккаунт владельца с указанным email и паролем из `OWNER_PASSWORD_HASH`. Он сохраняется в базе; последующее изменение переменной не меняет пароль существующего аккаунта. В разделе «Филиалы» владелец создаёт администраторов филиалов с отдельными паролями. Обычная регистрация всегда создаёт аккаунт клиента, общий для обоих филиалов.

Данные хранятся в SQLite по пути `DB_PATH` (по умолчанию `./data/studio.db`). При первом запуске база получает демонстрационные занятия, клиентов и записи. В дальнейшем данные не перезаписываются. При обновлении старой базы все существующие занятия, серии и абонементы относятся к первому филиалу; аккаунты, записи, остатки и история операций сохраняются. Карточки с одинаковым email без учёта регистра объединяются, их записи переносятся в одну карточку, а исходные данные остаются в таблицах `client_merge_archive` и `booking_merge_archive`.

Администратор выдаёт абонемент на 4 или 8 посещений с включительными датами начала и окончания. Владелец выбирает действие в одном филиале или в обоих. У клиента может быть несколько действующих абонементов; если для записи подходят несколько, он выбирает конкретный. Новая запись требует абонемента с остатком на дату занятия и подходящим филиалом. Списание и отмена записи проходят в транзакции; при отмене за 6 часов или раньше посещение возвращается в тот же абонемент, позже — место освобождается без возврата. Одинаковое правило действует для клиента и администратора. Перед отменой интерфейс показывает прогноз возврата. Отмена всего занятия администратором возвращает все невозмещённые списания за него, включая поздние отмены клиентов; занятие сохраняется со статусом «Отменено» в истории, повторная отмена ничего не начисляет. История списаний и возвратов доступна администратору. Записи, созданные до добавления абонементов, сохраняются без списания и при отмене не пополняют остаток.

Администратор может создать серию занятий по выбранным дням недели и периоду дат. Каждое повторение — отдельное занятие со своими участниками и местами. При редактировании можно изменить только выбранное занятие или его и следующие занятия серии. Отдельно изменённое занятие становится исключением и не затрагивается последующими групповыми правками. Сдвиг даты при групповом редактировании одинаково сдвигает даты следующих занятий; число экземпляров и записи остаются прежними. Отмена одного занятия не отменяет остальные.

В учебном прототипе регистрация с email существующей карточки сразу связывает аккаунт с этой карточкой и её записями. Подтверждения владения почтой пока нет: не используйте такой режим с реальными персональными данными в публичном интернете.

## Размещение на VPS

Направьте DNS-запись домена на сервер, установите Docker Compose, заполните `.env` с `DOMAIN`, `ADMIN_EMAIL` и `OWNER_PASSWORD_HASH`, затем запустите `docker compose up -d --build`. Caddy автоматически обслуживает HTTPS. База хранится в томе `studio-data`; включите этот том в резервное копирование. Порты 80 и 443 должны быть доступны извне.

## Проверка

`npm test` — правила записей и сохранность базы. `npm run build` — проверка TypeScript и производственная сборка.
